# Contributing to this Repo

Thanks for contributing! This repo holds the materials for a section of CS 377 (Ethical Issues in Computing) at UIC: slides, the syllabus, dilemmas, out-of-class exercises, and the "read a book" assignment. Everything here is published at [doethics.fun](https://doethics.fun/).

A quick pull request should work fine for things like:
* fixing a typo
* rephrasing a bulletpoint
* repairing a broken link
* adding a missing source or citation

If you want to make a larger change (e.g. a new dilemma, a new slide section, a redesigned page), consider opening a GitHub issue first.

Contributions are especially welcome from people using these materials, i.e. students in the course and TAs. Mention this in your issue or pull request.

## Making up a missed class

Students in the course can use a merged contribution to make up for a missed class.

- Up to two absences can be made up this way.
- Credit is decided case by case. If you are not sure whether an idea would count, ask before you start.
- To claim it, send me the link to your pull request (by email or a Canvas message), along with the date of the class you missed.
- Claims are due by the last day of class.
- Made-up absences still count toward the syllabus rule that students who miss more than half of all class sessions cannot pass the course.

## Setup

For prose-only fixes, GitHub's web editor is fine: open the file on GitHub, click the pencil icon, and GitHub will fork the repo and open a pull request for you.

For anything bigger, [fork the repo](https://docs.github.com/en/get-started/quickstart/fork-a-repo), then clone your fork. The [Overview](README.md#overview) table in the README lists which file to edit for each part of the site.

Key resources as you edit:

| Editing | You need |
| --- | --- |
| Slides (`docs/slides/week*.md`) | [Quarto](https://quarto.org/docs/get-started/) |
| Site pages, FAQ, schedule | Ruby + Bundler (for Jekyll) |
| Syllabus (`syllabus_source/`) | `pandoc`, `xelatex` |
| Dilemmas (`dilemmas/*.md`) | Python 3 (standard library only) |

If your website unessay is going on the site, follow [Publish Your Unessay as a Website](docs/unessays/how-to-publish.md) instead.

## Development

Commands for previewing the site and building the slides, syllabus, and dilemmas are in the "Technical details" sections of the [README](README.md#technical-details).

A few important conventions:

- The `.md` is the slide source. Edit `docs/slides/week*.md`, not `docs/slides/week*.html`: the HTML is regenerated by `docs/slides/build.sh` (and by CI on every push to `main`).
- Parts of `docs/slides/index.html` are generated by `docs/slides/sync_slide_index.py`. Don't hand-edit anything between its markers; change the deck's `{.section-header}` heading or the `Topic` column of `docs/_data/schedule.csv` instead.
- The schedule lives in two files: `docs/_data/schedule.csv` (the calendar) and `docs/_includes/schedule-topics.md` (what happens each day, plus sources). The schedule page and the syllabus both read from them. Add new CSV columns at the end only.
- Edit `syllabus_source/syllabus.md`, not `docs/syllabus/`, which is generated by `syllabus_source/build.sh`.
- Edit the dilemma sources in `dilemmas/`, not the generated pages in `docs/dilemmas/`. Each source needs a `summary:` line in its front matter.
- Use SVG for figures whenever possible. Reserve PNG/JPG for photographs, archival screenshots, etc. where a vector version isn't possible.
- Check citations against a primary source. Prefer sources with a DOI, which can be cross-checked with `https://api.crossref.org/works/<doi>`.
- Don't add Canvas-only materials. As the syllabus says, "do not upload course materials you did not create to third-party websites," which includes "worksheets, rubrics, and any readings posted behind the Canvas login."

## Opening a pull request

[GitHub flow](https://docs.github.com/en/get-started/quickstart/github-flow):

- Work on a branch, not `main`, and start from a recent `main`.
- Use meaningful commit messages: `fix broken link in week 4 slides`, not `fix`.
- In the PR description, say what changed and why.
- If you used an LLM to write a significant part of the change, please disclose it. This repo tracks that deliberately.
	- LLM-modified files should have a `NOTICE:` header of some kind
	- `sandbox/` is intended as a quarantine for LLM-generated and experimental work
	- See the "Note on AI/LLM use" section of the [README](README.md#note-on-aillm-use) for more details
- Link any issue your PR resolves so it closes on merge.
- Contributions are licensed the same way as the rest of the repo: CC BY-NC-SA 4.0 (see the License section of the [README](README.md#license)).

## After your change is merged

Woohoo! Thanks for contributing! Your GitHub profile should now show up under the 'Contributors' portion of the repo page.

Every push to `main` triggers `.github/workflows/deploy-site.yml`, which rebuilds any slides and dilemmas the push touched, runs Jekyll, and publishes to [doethics.fun](https://doethics.fun/). It's usually live a few minutes after the merge.
